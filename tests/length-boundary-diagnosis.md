# 先写后读在约 0x240 长度后大量报错

2026-11-05：用户报告相同时序下，长度约超过 `0x240` 后大量报错。
本次核查的硬件源码为 `a8dc374`；用户实际烧录源码版本尚未确认。本次仅增加回归和
诊断报告，没有为这个现象修改硬件 RTL 或生成新 bitstream，根因尚未确定。

用户随后提供的配置和日志：HS16M3A16AB、x16 随机数、WEN 写、Read1、50 ns、
起始地址 0、数量 `0x250`（592 字）、一轮。错误从 `0xBF` 开始，连续到 `0x24F`，
正好 401 条；`0xBF`–`0xC3` 读到 0，`0xC4` 起读到 `0x0800`。
用户确认读阶段 DQ 后段没有数据，此时 CE/OE/UB/LB 仍低、WE 仍高；Read2 对照也会
大量出错。这降低了 Read1 连续片选作为共同原因的可能性。尚缺实际地址总线波形和
同次实现时序报告，不能仅凭控制电平确定芯片或 FPGA 哪一侧有问题。

按地址周期计算，首错对应读阶段约 9.6 us，完整读阶段约 29.6 us。它并不是从
`0x240` 地址开始失败，也没有在 `0x200` 边界才开始出错。

## 已补充的数字回归

运行 `bash tests/run_random_pattern.sh`。独立存储模型在 CE/WE/字节使能结束有效
写窗口时，从实际 A/DQ 引脚保存数据；读阶段返回保存的字，并核对期望数据、
写入与采样的地址顺序、每轮完整覆盖和 SPI 汇总。

- 保留原有 10 个随机用例，包含 x8/x16、单地址、两轮测试、错误注入和启动替换。
- 新增 48 个随机用例：长度 511、512、575、576、577、1024、1025、16385，
  每个长度覆盖三种写模式和两种读模式。配置周期为 35 ns，Read2 自动提升到 40 ns。
- 新增 16 个固定数据用例：数据模式 1–8，Read1 长度 577、Read2 长度 1025，
  使用 WEN 写、35 ns 配置，每个用例两轮。
- 新增 6 个用户配置用例：起始地址 0、592 字、一轮、x16 随机数据、50 ns、
  开启详细日志，覆盖三种写模式及两种读模式。
- 存储数组与独立 Python PRNG 参考向量从 512 扩展到 32768 项。

首段和末地址的 Expect 可与同一 xorshift32 序列对应：从相邻值反推的本轮种子为
`c58ed660`，在 `0xBF/0xC0/0xC1/0xC2/0xC3/0xC4/0x24F` 对应
`e42a/948b/af38/2f42/10d0/976b/9a7d`。该序列在此次 592 个地址内没有
`0000` 或 `0800`，因此固定返回值不符合本轮已写序列中某个字的正常重复读取。
这仍不能排除写入、地址、总线驱动、器件输出或物理时序问题。

可用对应种子的数字夹具单独运行这 6 个配置（只影响仿真，不修改生产熵源）：

```sh
MRAM_TEST_SEED=c58ed660 bash tests/run_random_pattern.sh +repro_only
```

这 6 个配置用该种子也通过了全部 3552 次引脚写入、3552 次采样与 SPI 汇总检查，
没有复现 DQ 消失；原默认种子下的同组配置也通过。
默认种子全量 80 个用例通过，共观察到 284157 次写入（含被替换旧测试的 9 次写入）
和 284148 次有效读采样。独立引脚时序、854920 个谓词边界与 10 个完整普通报告
回归也通过；Tcl 报告新增部分仅用替代命令检查了执行流程，没有运行 Vivado。

数字模型使用确定性的种子夹具和固定 35 ns 地址到数据延迟；不模拟物理地址线、
CE/OE 输出关闭、板级延迟或布局布线违例。通过这些测试不能证明上板错误已经修复。

## 下一步需要的板上证据

保留失败 bitstream 和配置，上传 DQ 消失前后的原始逻辑分析仪波形（含实际 A、DQ、
CE/OE/WE/UB/LB）及同次实现的 `timing_bundle_*.rpt`，确认地址是否仍连续变化、
读使能在器件端是否有效，以及内部地址/控制/采样路径的 setup/hold。
目录 Git HEAD 本身不能证明实际烧录的 bitstream 就由该版本生成。

时序报告可在 Vivado 打开同次 Implemented Design 后运行：

```tcl
source E:/workspace/xilinx_workspace/MRAM_EVB/tests/collect_spi_timing.tcl
```

脚本已补充 `address_count.rpt`，单独报告地址计数、副本、地址生成及输出命令寄存器
发出的路径，包含正裕量路径，避免它们被全局最差路径列表淹没。不改变约束或设计。

若还需进一步定位长度与地址的关系，可用同一 bitstream 做以下比较：

1. 使用递增数据、起始地址 0，比较长度 `0x1FF`、`0x200`、`0x23F`、`0x240`、
   `0x241`、`0x400`。记录首个错误地址、实际值和期望值。
2. 对失败长度改变起始地址，判断错误边界跟随绝对地址还是相对计数。
3. 保持其他配置一致，将周期加长到 50 ns 或 75 ns，对照错误是否减少。
   这只能说明配置敏感性，不能代替 200 MHz 内部时序检查。

当长度单位为地址/字且起始地址为 0 时，`0x240` 表示访问地址 `0`–`0x23F`，
已跨过 A9 在 `0x200` 处的翻转。递增模式下，实际值与期望值相差 `0x200` 或
呈现固定地址覆盖关系，是检查 A9/地址混叠的线索；不能仅凭长度认定地址线故障。

即使内部 WNS/WHS 均通过，也仍需核对外部 MRAM 的实际有效窗口；当前约束并未
建立完整的板级 MRAM 输入/输出时序预算。
