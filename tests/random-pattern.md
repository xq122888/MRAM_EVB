# TRNG 种子与可重放随机数据

分支：`fix/random-data-pattern`。基于已通过时序的详细日志源码 be92d26 及文档提交
6091834。本分支改变了 RTL、TRNG 和时序约束，必须重新综合、实现及上板验证；
be92d26 的时序结果不代表本次实现。仓库中继承的 bitstream 不包含本次修复。

## 原问题与当前行为

配置字节 3 的值 9 表示随机数据。原先每个 16 位字是把
`trng_data_reg ^ addr_cnt[7:0]` 复制两次，所以会出现 C0C0、C1C1、C2C2 等地址规律。
原熵字节的产生速度也远慢于 MRAM 字更新速度，读阶段使用实时熵无法保证重放写入值。

现在的数据流是：

```text
5 个物理振荡环 → 两级同步 → 定时采样 → 去偏及基本健康检查
    → 新鲜的 32 位种子 → 本次测试保存种子 → PRNG 生成数据字
                                      └→ 读阶段恢复本轮种子，重放期望数据
```

每次有效的随机测试命令消耗一个新的 TRNG 种子，保存在 `random_test_seed`。
每一轮保存自己的 `random_seed`，读阶段恢复它；后续轮次推进子种子，保持可重放。
同模式重新启动必须重新消耗新种子，不能重复使用上次缓存。

x16 从 xorshift32 状态取低 16 位，两个字节不再被强制设为相同；x8 仍取低字节，
内部总线沿用字节复制方式。错误明细进入独立 FIFO，PRNG 与写读流水线连续运行；
等待新 TRNG 种子仍保持启动前等待。
随机模式的单地址写读测试也避免了读结束后额外写零的原控制边界问题。
其他数据模式保留原有控制行为。

若新种子尚未就绪，SPI 启动请求会等待，MRAM 不开始新的写入；等待替代测试时停止旧引擎。
新有效配置可替代等待请求，停止命令可取消等待，错误校验帧不会替换有效等待配置。
不使用固定种子或时钟计数值冒充熵源。上位机继续使用原配置与报告格式，无需新增字段。
保存的种子用于 FPGA 内部重放，现有 SPI 报告不包含种子字段。

## TRNG 与故障处理

`trng_ro.v` 使用 5/7/9/11/13 级的五个奇数反相环，每级为显式的保留 LUT1。
RO 输出先进入两级同步器，再由原 200 MHz 主时钟下的计数使能采样；不再产生采样派生时钟。
默认每 128 个主时钟采样一次，Von Neumann 去偏丢弃 00/11，保留 01→0、10→1。
首次通过一个 256 位原始采样窗口的基本检查后，才允许输出有效熵字节。
每 8 个接受位产生一个熵字节，每 4 个熵字节组成候选种子。

基本检查包括：

- 连续 64 个原始采样位相同则锁存故障。
- 每 256 个原始采样位中的 1 少于 32 或多于 224，则锁存故障。
- 连续 65,536 个主时钟没有产生有效熵字节，则锁存故障。
- 候选种子为全 0、全 1 或等于上次已消费种子时，丢弃重取；连续 8 个被丢弃则锁存故障。

种子缓存满后保持不变，直到启动握手消费；消费后重新收集，不能重复交付同一个缓存。
熵源故障会抑制新的种子就绪信号，没有固定值后备。故障锁存需通过板级复位清除。
如果随机测试持续等待，应先检查下列信号：

| 信号 | 含义 |
| --- | --- |
| `random_seed_wait` | 等待种子的 SPI 启动请求 |
| `trng_seed_ready` | 一个完整的新鲜种子已就绪 |
| `trng_seed_fault` | 熵源或种子检查故障 |
| `random_test_seed` | 本次测试实际使用的 TRNG 种子 |
| `random_seed` | 本轮写读重放使用的子种子 |
| `u_seed_rng/u_entropy/raw_bit`、`sample_tick` | 同步后的原始采样及采样时刻 |

本版按用户要求已去掉 ILA 和 MARK_DEBUG；上述为 RTL 状态名，当前 bitstream 不提供其探针。
需要重新加入片内调试时，应另外综合并验证时序，不能加载旧 ltx 冒充当前设计。

这些检查只能排除部分明显异常，不能证明物理熵率、独立性或提供密码学随机性认证。
RO 频率、耦合、采样混叠和温压条件都需上板评估。仅观察不同种子或 PRNG 输出变化，
不能证明 TRNG 的随机质量；还应采集按 `sample_tick` 标记的原始样本分析。
不同种子的单个 16 位数据字也可能偶然相同，这是正常现象。

## 时序边界

主时钟仍为 5.000 ns。时序例外仅限：

- 对明确的 RO 环内网络设置 `ALLOW_COMBINATORIAL_LOOPS`。
- 对物理 RO 到第一级 `ro_meta` 同步器 D 引脚设置假路径。

第一级到第二级同步、采样计数、去偏、健康检查、种子缓存及 PRNG 均保留正常时序分析。
原先整个 TRNG 模块的宽泛假路径已移除。时序收集脚本会记录种子寄存器、RO 环网络和
第一级同步器引脚的匹配数量，辅助检查载入的设计与约束。

## Vivado 2018.3 XDC 兼容性修复

41e4cb9 的 timing.xdc 使用了 Tcl `if`，Vivado 2018.3 的 XDC 解析器不支持，
导致振荡环许可未应用，产生 LUTLP-1 并阻止 bitgen。现在改为直接的 XDC 命令：
只允许 45 个指定 RO 环网络的组合环，仅排除 5 个第一级同步器 D 引脚的异步路径。
不降低 LUTLP-1 的严重级别，也不排除普通同步逻辑的时序。

debug.xdc 清除创建调试核之前的旧 UART / 中间设计连接，保留最后的 32 个 SPI ILA
探针定义；先创建核心再连接探针。probe18 改为实际 `spi_miso_OBUF`，dbg_hub 的
输入频率属性改为实际 200 MHz。需要使用新生成的匹配 `.ltx`。

```sh
tclsh tests/check_xdc.tcl
```

该测试用受限命令解释器检查 XDC 命令集、45 个 RO 网络和 5 个同步器入口的匹配范围、
ILA 核心/探针创建顺序、32 个探针宽度、MISO 连接及调试时钟。
它不替代 Vivado 对实际网表对象、DRC 及布局布线的验证。

Reset 综合及实现后重新收集 bundle。脚本会记录 RO 许可属性已生效的数量
（本设计预期 45/45）、第一级同步器匹配数量（预期 5），并附加 LUTLP-1 DRC 报告。
时序不满足仍需根据新的 setup/hold 报告继续分析，不能仅凭解析错误修复就认定时序通过。

## 2026-11-04 12:52 报告后的时序优化

`timing_bundle_20261104_125247.rpt` 对应 d9d95b1：RO 环网络许可 45/45，
第一级同步器入口 5 个，LUTLP-1 无违例，bitstream 已生成。
但主时钟 setup WNS 为 −0.275 ns、TNS 为 −10.364 ns，共 98 个失败端点；
hold 最差 +0.052 ns、无失败端点。因此该结果仍不能作为 200 MHz 时序通过的依据。

失败路径主要落在地址计数比较、周期计数器更新及其控制扇出，另有一条 SPI 发送路径。
本次候选修改包括：

- 为地址比较增加同沿更新的 23 位计数副本，分离地址/数据/调试负载与比较负载；
  复位、清零、使能与原计数器一致，不引入额外时钟延迟。
- 保留最终周期比较节点，拆开计数器高位清零与最低位装载 0/1 的逻辑，
  并限制共享计数控制网络的扇出。
- 将 SPI 帧长度减法限制到 5 位，避免无尺寸常量导致的 32 位减法链；
  保留原零长度下溢行为，穷举全部 32×32 个长度/指针组合验证等价。

控制回归逐周期检查地址副本与原计数器一致；详细日志冻结检查也包含该副本。
上述仿真通过只验证数字功能，时序改善必须以重新综合和布局布线后的报告为准。
收集脚本新增地址比较副本寄存器计数，预期 23 个，辅助确认加载了新网表。
