# MRAM 明确时序与 IOB 接口

本说明更新 cc2b734、4ea7962 的旧波形表，以用户确认的时点为验收标准。
当前基于 `31100b0`，分支为 `rollback/pre-data-types`，必须重新综合、实现及上板复测。
云端没有 Vivado，本次只能验证 RTL 行为，尚不能确认实际 IOB 放置或 200 MHz 时序。

2026-11-06：Read1 实际采样由 +40 ns 调整为 +45 ns，与 Read2 一致；
Read1 的连续低有效控制及配置访问周期保持原约定，末地址保持至采样。

## 时间定义

外部地址及写数据开始有效为 0 ns，主时钟一拍 5 ns。
写周期为 P 拍，Read1 读周期为 R 拍；Read2 读周期自动取 max(P,8)。
Read2 配置 35 ns 时，写周期仍为 35 ns，读周期提升至 40 ns。

| 模式 | CEN 拉低 / 拉高 | WEN 拉低 / 拉高 | UBN/LBN 拉低 / 拉高 | OEN | 实际 DQ 锁存 |
| --- | --- | --- | --- | --- | --- |
| CEN 写 | 1 / P−3 拍 | 0 / P−2 拍 | 0 / P−2 拍 | 常高 | — |
| WEN 写 | 0 / P−2 拍 | 1 / P−3 拍 | 0 / P−2 拍 | 常高 | — |
| BN 写 | 0 / P−2 拍 | 0 / P−2 拍 | 1 / P−3 拍 | 常高 | — |
| Read1 | 常低 | 常高 | 常低 | 常低 | 固定第 9 拍（45 ns） |
| Read2 | 1 / R 拍 | 常高 | 1 / R 拍 | 第 1 拍低、第 R 拍高 | 固定第 9 拍（45 ns） |

35 ns 写周期：主控信号 5 ns 拉低、20 ns 拉高，另外两个使能 0 ns 拉低、25 ns 拉高。
50 ns 写周期：下降沿不变，主控信号 35 ns 拉高，另外两个使能 40 ns 拉高。
Read2 周期加长时，CEN/OEN/BN 的上升沿一起推迟，实际 DQ 锁存时刻仍为 45 ns。
首地址、后续地址和每次循环首地址使用同一起点，起始地址为 0 也不例外。
当前 x16 的 UBN/LBN 同时动作，未分别测试高、低字节。
x8 仍覆盖 BN 为有效状态，BN 控制写仅适用于 x16。

## 采样、比较与收尾

每次读访问启动时保存该地址和期望值，两组独立的倒计时记录允许短周期读重叠。
Read1 和 Read2 均在 +45 ns 由 DQ 输入寄存器实际锁存，再在下一拍比较。
这不是提前采样后将比较时间标为采样时间。
最后一个地址也会等到实际采样，防止最后一个周期结束时提前释放地址或漏检。
Read1 的 35 ns 周期在末地址额外保持至 +45 ns；收尾期间计时器回零不会触发控制信号拉高。
SPI 汇总必须等待全部采样、比较和错误计数完成，详细日志的地址/数据与采样记录配对。
同模式新命令会清空旧采样记录及各级读写方向，避免旧读记录污染新首写周期。
写读转换还恢复所有数据模式的首字，避免奇数长度/单地址情况下交替数据反相。

Read1 周期 35 ns 时，连续访问的 +45 ns 锁存位于下一地址开始后 10 ns；
最后地址会额外保持至采样。Read2 周期 40 ns 时，控制信号 +40 ns 关闭，+45 ns 锁存。
这两种跨边沿采样均需要结合实际 MRAM 输出变化/保持特性验证。
尤其 Read2 需要器件在关输出后继续提供覆盖 5 ns 并满足 FPGA 建立/保持的数据，
IOB 不能保证该器件行为。如果数据已变为高阻，RTL 和 IOB 都无法恢复有效值。
测试中的 10 ns 输出保持只是明确的数字夹具假设，不能代替器件手册或板上测量。

## IOB 组织与验证

MRAM 接口的最后一级寄存器设置 `IOB=TRUE`，并保留独立寄存器，目标为：

| 部分 | 寄存器数量 |
| --- | --- |
| 地址 A | 22 |
| CEN/WEN/OEN/UBN/LBN | 5 |
| DQ 输出数据 | 16 |
| DQ 三态使能 T | 16 |
| DQ 输入采样 | 16 |
| 合计 | 75 |

控制器先生成一组命令寄存器 `pad_cmd_*`（44 个 FF），下一拍由 IOB 寄存器直接读取它们的 Q。
IOB 的 D 路径只剩寄存器间连接，不再在最后一拍串行执行周期比较、活动状态和模式选择。
地址、数据、CEN/WEN/OEN/BN 和 DQ 三态使能全部一起后移一拍。
这是从启动命令到首地址多 5 ns，不改变以上表格相对于实际引脚地址起点的时刻。

采样调度同时补偿这一拍：以控制器命令为参考，Read1/Read2 均在 +50 ns 锁存；
以实际引脚地址起点为参考，均为 +45 ns。最后地址的释放也按 IOB 流水提前安排，
保证在实际锁存边沿之前仍保持地址/方向。SPI 汇总等待引脚访问与采样/比较流水全部完成。

周期结束事件从前一拍的 P−1 条件预测并寄存，运行时不再把大比较器接在多级活动控制前面。
地址计数更新所需的终值/范围判断先寄存；对支持的 P>=7，在 P−2 更新计数时已经稳定。
测试对每个有效计数更新沿检查预测值与原组合判断相同，没有改变计数更新或引脚间隔。

**按用户要求已去掉 ILA 和 debug_hub**，debug.xdc 只保留说明，活动 RTL 的 MARK_DEBUG 也已移除。
不再需要片内 ILA 镜像或探针配置。原先用于反馈/观测的寄存器现用于输出命令流水，
不增加第二组同沿调试副本。块 RAM 和逻辑的实际减少量以新实现报告为准。
编程时应清空 Hardware Manager 中旧 ltx 的探针文件配置，使用新生成的 bit。

`tests/collect_spi_timing.tcl` 会记录 75 个物理 IOB 寄存器的 LOC/BEL、44 个命令 FF、
注册的周期事件和 ILA/debug_hub 数量（预期 0）。200 MHz 内部时序和外部器件时序仍需验证。

## 连续访问与错误 FIFO

错误记录先进入 4096 条 BRAM FIFO，由 SPI 独立发送，不再冻结 MRAM 计数、地址或控制引脚。
即使缓存满也继续按指定时序测试，只丢弃新的明细；总错误数仍完整累计。
溢出/丢失计数仍在 RTL 中保留，但本版没有 ILA 探针；现有 25/17 字节帧格式保持不变。
上位机用每轮汇总总数减去有效、去重后的明细数量判断未收到的明细。
详细约定见 [detailed-error-log.md](detailed-error-log.md)。
轮内访问连续；轮间仍等已缓存明细排空、汇总完整读取后才开始下一轮。
Read1 的 CEN/OEN 本来保持低，判断单次读周期应看地址切换间隔，而不是整个低脉冲宽度。

## 2026-11-04 16:45 实现结果与后续候选

125 个 setup 失败端点；hold 最差 +0.030 ns、无失败。RO 许可 45/45，LUTLP-1 无违例。

因此此前的 IOB 属性只部分生效，不能认定输出已经进入 IOB。
报告中的 77 候选包含误计的 2 个 CARRY4，实际寄存器数量是 75。

本次候选隔离物理输出 Q 的反馈/调试负载，改用同沿片内镜像；输出和三态寄存器连续时钟更新，
不依赖从自身 Q 返回片内保持逻辑。该结构移除了打包障碍，是否成功仍需新布局布线验证。
周期比较器改为在父层直接合并两个参数组的部分比较结果，目标是去掉报告中分组匹配之后
额外的 AND/OR 逻辑级；计数清零控制限制扇出，输入 IFF 去除慢 CE 路径。

收集脚本现仅计数 FD* 寄存器，分别汇总实际 I/O logic 和 SLICE 数量，
列出物理 Q 的负载，并附带 synth_2 / impl_2 的 IOB 打包日志，以便检查仍未打包的原因。
