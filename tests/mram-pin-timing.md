# MRAM 明确时序与 IOB 接口

本说明更新 cc2b734、4ea7962 的旧波形表，以用户确认的时点为验收标准。
分支为 `fix/random-data-pattern`，必须重新综合、实现及上板复测。
云端没有 Vivado，本次只能验证 RTL 行为，尚不能确认实际 IOB 放置或 200 MHz 时序。

## 时间定义

外部地址及写数据开始有效为 0 ns，主时钟一拍 5 ns。
写周期为 P 拍，Read1 读周期为 R 拍；Read2 读周期自动取 max(P,8)。
Read2 配置 35 ns 时，写周期仍为 35 ns，读周期提升至 40 ns。

| 模式 | CEN 拉低 / 拉高 | WEN 拉低 / 拉高 | UBN/LBN 拉低 / 拉高 | OEN | 实际 DQ 锁存 |
| --- | --- | --- | --- | --- | --- |
| CEN 写 | 1 / P−3 拍 | 0 / P−2 拍 | 0 / P−2 拍 | 常高 | — |
| WEN 写 | 0 / P−2 拍 | 1 / P−3 拍 | 0 / P−2 拍 | 常高 | — |
| BN 写 | 0 / P−2 拍 | 0 / P−2 拍 | 1 / P−3 拍 | 常高 | — |
| Read1 | 常低 | 常高 | 常低 | 常低 | 固定第 8 拍（40 ns） |
| Read2 | 1 / R 拍 | 常高 | 1 / R 拍 | 第 1 拍低、第 R 拍高 | 固定第 9 拍（45 ns） |

35 ns 写周期：主控信号 5 ns 拉低、20 ns 拉高，另外两个使能 0 ns 拉低、25 ns 拉高。
50 ns 写周期：下降沿不变，主控信号 35 ns 拉高，另外两个使能 40 ns 拉高。
Read2 周期加长时，CEN/OEN/BN 的上升沿一起推迟，实际 DQ 锁存时刻仍为 45 ns。
首地址、后续地址和每次循环首地址使用同一起点，起始地址为 0 也不例外。
当前 x16 的 UBN/LBN 同时动作，未分别测试高、低字节。
x8 仍覆盖 BN 为有效状态，BN 控制写仅适用于 x16。

## 采样、比较与收尾

每次读访问启动时保存该地址和期望值，两组独立的倒计时记录允许短周期读重叠。
Read1 在 +40 ns、Read2 在 +45 ns 由 DQ 输入寄存器实际锁存，再在下一拍比较。
这不是提前采样后将比较时间标为采样时间。
最后一个地址也会等到实际采样，防止最后一个周期结束时提前释放地址或漏检。
SPI 汇总必须等待全部采样、比较和错误计数完成，详细日志的地址/数据与采样记录配对。
同模式新命令会清空旧采样记录及各级读写方向，避免旧的暂停读污染新首写周期。
写读转换还恢复所有数据模式的首字，避免奇数长度/单地址情况下交替数据反相。

Read1 周期 35 ns 时，连续访问的 +40 ns 锁存位于下一地址开始后 5 ns；
最后地址会额外保持至采样。Read2 周期 40 ns 时，控制信号 +40 ns 关闭，+45 ns 锁存。
这两种跨边沿采样均需要结合实际 MRAM 输出变化/保持特性验证。
尤其 Read2 需要器件在关输出后继续提供覆盖 5 ns 并满足 FPGA 建立/保持的数据，
IOB 不能保证该器件行为。如果数据已变为高阻，RTL 和 IOB 都无法恢复有效值。
测试中的 10 ns 输出保持只是明确的数字夹具假设，不能代替器件手册或板上测量。

## IOB 组织与验证

MRAM 接口的最后一级寄存器设置 `IOB=TRUE`，并保留独立寄存器，目标为：

| 部分 | 寄存器数量 |
| --- | --- |
| 地址 A | 22 |
| CEN/WEN/OEN/UBN/LBN | 5 |
| DQ 输出数据 | 16 |
| DQ 三态使能 T | 16 |
| DQ 输入采样 | 16 |
| 合计 | 75 |

输出寄存器之后不再有 flg/模式组合选择；活动状态和方向判断合并到寄存器输入。
DQ 每位独立的 T 寄存器直接控制引脚三态，避免一个方向寄存器扇出到所有 IOB。
输入采样寄存器按原时钟锁存，错误比较在下一拍进行，控制引脚没有因此整体多延迟一拍。
只设置 IOB 属性不代表物理实现已经打包成功。

`tests/collect_spi_timing.tcl` 会记录候选寄存器数量以及每个寄存器的 IOB、LOC、BEL，
新布局布线报告应核对实际 ILOGIC/OLOGIC/IOB 放置。
若属性与实际位置不同，应根据日志和器件资源继续调整，不能只凭属性值宣称全部进入 IOB。
200 MHz 内部时序、外部器件建立/保持和板级延迟仍需分别验证。

ILA probe1 现在观察 `dq_read_data`，即输入寄存器结果，需要使用同次生成的 ltx。
probe4 观察 `dq_write_data` 的 16 位输出寄存器，源码标记保留该调试网络。
原 `DQ_OBUF` 是旧输出结构的综合网络别名，不能用于当前双向 IOB 结构；
否则会在 XDC 连接时返回空网络，并导致 probe4 的 16 个通道全部未连接。
ILA 同时钟观测该 Q 会比实际 DQ 锁存晚一拍，对应 `read_compare_valid`；
按需用 Set Up Debug 添加 `read_sample_valid` 和 `read_compare_valid` 以区分锁存与比较。

## 数字验证与本机操作

```sh
bash tests/run_top_timing.sh
bash tests/run_random_pattern.sh
bash tests/run_spi_detail.sh
bash tests/run_spi_reports.sh
bash tests/run_trng_seed.sh
tclsh tests/check_xdc.tcl
```

引脚检查通过真实 SPI 配置及报告 ACK 驱动三轮访问，独立计算每拍地址、控制信号、
采样时刻及采样地址/期望值，不强制配置或控制信号。
覆盖三种写、两种读、全部写读组合、Read2 自动提速、7/8/9/10/35/255 拍配置、
零/非零起址、单/多地址、x8 和同模式重启，并检查 IOB 锁存与下一拍比较的配对。
本次通过 142 组配置、426 轮访问、65,490 个引脚周期及 912 个地址/数据配对锁存，
另通过 854,920 个边界条件、10 个完整普通报告、753 次随机写入及 24 条完整错误明细。
详细日志回归还覆盖有旧错误记录时替换当前测试，暂停时保持整个采样流水。

关闭本机 Vivado 后拉取分支，Reset synth_2，重新综合及实现。
Open Implemented Design 后运行收集脚本，上传新的 timing bundle，检查 IOB 位置及 setup/hold。
时序满足后烧录同次 bit/ltx，并按上述表抓取每种模式首轮与后续轮次的首周期。
