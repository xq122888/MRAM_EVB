# MRAM 首周期与循环重启时序修复

本说明对应 `fix/random-data-pattern` 上、cc2b734 之后的引脚控制修复。
此前的稳态时序说明不能覆盖首个地址、循环重启和单地址边界。
本次没有运行 Vivado，须重新综合、布局布线并上板复测。

## 原因与修改

原引脚逻辑混用了启动延迟、地址是否变化以及周期计数三种触发条件。
零偏移信号依赖地址变化，不能可靠覆盖地址 0、同一地址重访和循环首地址；
后续循环的 `flg` 还比周期计数重启早一拍打开，可能暴露尚未准备好的地址、数据和旧引脚状态。

新增 `io_cycle_start`，以周期计数重启或有效访问周期结束为共同起点。
每个引脚在该起点明确初始化到本周期应有的电平，再按计数执行后续边沿。
循环启动先释放外部接口，准备起始地址和数据，随后与计数器一起打开接口。
DQ 的零延迟装载也使用同一起点，不再依赖地址是否改变。

写阶段 OEN 始终为高，读阶段 WEN 始终为高。
这修复了原写 OEN 在同一计数同时命中拉低、拉高条件而优先拉低的问题。
单地址情况下，仅写转读时允许计数回绕，最终访问必须推进到结束条件，避免额外写周期。
错误明细背压仍冻结当前访问状态。

## x16 波形验收

以外部地址/写数据开始有效为 0 ns，时钟一拍 5 ns，周期为 `P` 拍。
以下时点适用于首个地址、后续地址、每次循环首地址；数字时点未包含引脚/板级传播延迟。

| 写模式 | CEN 拉低 / 拉高 | WEN 拉低 / 拉高 | UBN/LBN 拉低 / 拉高 |
| --- | --- | --- | --- |
| CEN（00） | 1 / P−3 拍 | 0 / P−2 拍 | 1 / P−3 拍 |
| WEN（01） | 1 / P−1 拍 | 2 / P−2 拍 | 0 / P−2 拍 |
| BN（10） | 1 / P−1 拍 | 1 / P−1 拍 | 2 / P−2 拍 |

例如 50 ns 周期（P=10）：

- CEN 写：0 ns 地址/数据就绪且 WEN 低，5 ns CEN/BN 低，35 ns CEN/BN 高，40 ns WEN 高。
- WEN 写：0 ns 地址/数据就绪且 BN 低，5 ns CEN 低，10 ns WEN 低，40 ns WEN/BN 高，45 ns CEN 高。
- BN 写：0 ns 地址/数据就绪，5 ns CEN/WEN 低，10 ns BN 低，40 ns BN 高，45 ns CEN/WEN 高。

三种写模式的 OEN 均保持高，写数据保持到下一地址。
35 ns 周期（P=7）仍按上表执行，有效写窗口为 15 ns；50 ns 周期的有效写窗口为 30 ns。
周期并不等于有效写脉宽，是否符合具体芯片要求需要核对器件手册。
当前 x16 的 UBN/LBN 同时动作；x8 覆盖 BN 参数，仅 CEN/WEN 写纳入验证。

ADDR 读（00）：读段内 CEN/OEN/BN 持续低、WEN 高，地址按周期改变。
OEN 读（01）：0 拍 CEN/OEN/BN 高，1 拍 CEN/BN 低，2 拍 OEN 低，下一周期重置。
两种读阶段 FPGA 均释放 DQ。

读比较时刻仍采用原有 9 拍及上一地址比较分支，本次没有改变读采样策略。
尤其 35/40 ns 周期下跨地址比较是否有效，仍需结合 MRAM 访问/保持时间及实测确认。
开启详细日志会延长被暂停的访问周期，测量正常周期时应关闭详细日志。

## 验证方式与边界

```sh
bash tests/run_top_timing.sh
bash tests/run_random_pattern.sh
bash tests/run_spi_detail.sh
```

`run_top_timing.sh` 运行独立引脚检查、854,920 个算术/比较边界检查和完整 SPI 报告检查。
引脚专项也可单独运行 `bash tests/run_mram_pins.sh`。

引脚专项发送真实 SPI 配置，并完整读取每次循环报告以 ACK，配置和控制信号均不强制。
它独立计算每拍期望地址、电平、写数据和访问总拍数，检查全部地址和每轮首地址，
覆盖三种写、两种读、全部写读组合、7/8/9/10/35/255 拍周期、零/非零起址、
单/多地址、连续三轮、x8 配置及无板级复位的同模式重启。
本次通过 118 组配置、354 轮完整访问、21,018 个引脚周期检查，
以及 854,920 个边界条件和 10 个完整普通报告；随机数据重放与详细日志回归也通过。
读总线模型按外部 CE/WE/OE/BN 实际组合驱动，避免内部模式信号隐藏写时输出争用。
它不模拟 MRAM 的模拟延迟、板级走线或 FPGA 实现时序。

旧版 a317d2b 逐周期等价回归验证的是对旧行为的保留，无法证明旧行为符合期望时序。
它已被独立引脚检查取代，不再要求新首周期波形等于有缺陷的旧波形。
历史文档中的 617,129 周期等价结果是此前提交的历史验证，不代表本次引脚修复。

本机拉取后 Reset `synth_2`，重新综合、实现，并收集新的 timing bundle。
在时序通过后烧录同次生成的 bitstream，分别抓取每种模式第一轮和第二/三轮的首地址，
并同时观察 A、DQ、CEN、WEN、OEN、UBN/LBN。原有 bitstream 不包含本次修复。
