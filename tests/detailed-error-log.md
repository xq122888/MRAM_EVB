# 详细错误日志

本功能最初在 `feat/detailed-error-log` 开发，当前版本位于 `fix/random-data-pattern`。
当前采用 4096 条 BRAM FIFO，错误日志不会暂停 MRAM 访问；容量不足时继续测试并计数丢弃。
现有 25 字节明细和 17 字节汇总格式保持不变。
新的 x16 数据表与 March C 规则见 [data-patterns.md](data-patterns.md)。
模式 1/2 写读的全部阶段共享整轮计数和 FIFO；March C 在模式 0/1 下也使用
17/25 字节报告，错误总数可能大于地址数，需要上位机支持该新组合。
历史源码 be92d26 的时序通过结果不能用于本次 FIFO/IOB 版本，须重新综合、实现及上板验证。
仓库继承的 bit/ltx 未包含本次修改，云端未运行 Vivado。

## 启用与输出

在原有 24 字节配置命令中，设置测试模式 `T_MODE=2`（先写后读），
并将从 0 开始编号的 **字节 19** 设为 `0x01`。
March C 则使用 `din_sel=10`、`T_MODE=0/1`，字节 19 同样控制明细开关。
关闭明细时 March C 仍发送包含错误总数的 17 字节汇总。
Word 文档的配置表使用字节 19；后续文字写成字节 18，与表格冲突。
本实现使用表格定义，字节 18 仍为读模式。

每次比较发现错误，FPGA 将地址、实际读值、期望值及原错误序号写入 FIFO；
SPI 独立读取已缓存的记录并发送以下帧。缓存满时丢弃新明细，但仍累计总错误数。
所有多字节字段均为小端序。

| 字节 | 内容 |
| --- | --- |
| 0 | `55` |
| 1 | `19`（十六进制帧长，即 25 字节） |
| 2 | `FF` |
| 3–6 | 当前循环序号，沿用原有从 0 开始的编号 |
| 7–10 | 本轮配置的测试长度 |
| 11 | `01`（错误标志） |
| 12–15 | 本轮错误序号，从 1 开始，每轮重新计数 |
| 16–19 | 错误地址，保留内部完整 22 位，其余位补零 |
| 20–21 | 比较时的实际读值，16 位 |
| 22–23 | 本次比较使用的期望值，16 位 |
| 24 | `AA` |

文档为地址分配了 4 字节但标注 `err_addr[15:0]`。这里不截断高位，
避免大容量测试的地址混淆。地址单位沿用 FPGA 的字地址。

本轮所有已缓存明细发送后，仍发送原有的 **17 字节循环汇总帧**（`55 11 FF ... AA`），
其中错误标志由累计错误数决定，错误数是本轮总数。
只有汇总帧完整读完才确认本轮完成、允许进入下一轮；明细帧不会推进循环。
没有错误时只发送汇总帧。关闭详细日志时只发送汇总帧。
模式 0/1 仍使用原有 11 字节完成帧，即使字节 19 为 1 也不发送明细。

## 缓冲与轮询

FPGA 比较速度远高于 SPI 传输速度。当前使用同一 200 MHz 时钟下的 BRAM FIFO，
默认容量为 **4096 条**，每条存储 86 位（错误序号 32、地址 22、实际值 16、期望值 16）。
有效负载约 43 KiB，实际 RAMB 占用需以 Vivado 综合报告为准。容量包含预取的队头，不是 4096+1。
FIFO 模块放在现有 spi.v 内，不需要额外添加 XPR 源文件。

错误记录入队与 SPI 发送独立进行，队列非空或队满都不暂停 MRAM。
队满时不覆盖未读记录，继续测试、累计所有错误，并增加明细丢弃计数。
主机读出一条后释放一个槽位，后续新错误可继续入队；它保留原错误序号，因此溢出后可能跳号。
只有完整读完明细帧才消费队头，部分读取不释放槽位，下次轮询仍发送同一记录。

本轮 MRAM 读阶段结束后，先排空全部已缓存明细，再发汇总；
汇总完整读取后才进入下一轮。因此轮内保持连续时序，轮间仍可能等待 SPI/USB。

溢出标志 `detail_fifo_overflow` 与本轮丢弃计数 `detail_dropped_count` 仍保留在 RTL 中，
在新配置、新测试或本轮汇总 ACK 时清零。本版按用户要求去掉 ILA，不再提供 probe32/33。
主机不增加新字段：对每轮完整、有效的 25 字节明细按 `(loop_idx,err_idx)` 去重，
用汇总总错误数减去明细条数计算未收到的明细数；不要把原始 chunk 或重读重复帧重复计数。
无链路/解析丢失时，该差值等于 FIFO 丢弃数；差值本身不能排除通信丢帧。

保持原有 SPI 模式 0、每次 CS 最多一帧的约定；上位机可继续每次读取 64 字节。
有效帧结束后填零；没有就绪帧时整次轮询返回零。不要因为读到一条明细就认为本轮结束。
读帧中途拉高 CS 不消费记录，下次 CS 从帧头重新发送。
接收有效的新配置并启动新测试时会清除旧的待发送记录和完成事件。

错误快照使用实际 DQ 输入寄存器及该读访问保存的地址/期望值。
Read1 固定在 +40 ns、Read2 固定在 +45 ns 锁存，下一拍比较；
采样、末地址收尾和 IOB 接口详见 [mram-pin-timing.md](mram-pin-timing.md)。
FIFO 不改变这些时点。
