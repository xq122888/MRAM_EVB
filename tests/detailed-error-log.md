# 详细错误日志

本功能在 `feat/detailed-error-log` 分支开发。适用于支持 25 字节错误帧的上位机。
云端进行了 RTL 仿真；本功能还需要重新综合、实现及上板验证。
分支内继承的 `top.bit`、`.ltx` 和实现结果没有重新生成，不包含本次功能。

## 启用与输出

在原有 24 字节配置命令中，设置测试模式 `T_MODE=2`（先写后读），
并将从 0 开始编号的 **字节 19** 设为 `0x01`。
Word 文档的配置表使用字节 19；后续文字写成字节 18，与表格冲突。
本实现使用表格定义，字节 18 仍为读模式。

每次比较发现错误，FPGA 保存当时的地址、实际读值、期望值及序号，发送以下帧。
所有多字节字段均为小端序。

| 字节 | 内容 |
| --- | --- |
| 0 | `55` |
| 1 | `19`（十六进制帧长，即 25 字节） |
| 2 | `FF` |
| 3–6 | 当前循环序号，沿用原有从 0 开始的编号 |
| 7–10 | 本轮配置的测试长度 |
| 11 | `01`（错误标志） |
| 12–15 | 本轮错误序号，从 1 开始，每轮重新计数 |
| 16–19 | 错误地址，保留内部完整 22 位，其余位补零 |
| 20–21 | 比较时的实际读值，16 位 |
| 22–23 | 本次比较使用的期望值，16 位 |
| 24 | `AA` |

文档为地址分配了 4 字节但标注 `err_addr[15:0]`。这里不截断高位，
避免大容量测试的地址混淆。地址单位沿用 FPGA 的字地址。

本轮所有明细发送后，仍发送原有的 **17 字节循环汇总帧**（`55 11 FF ... AA`），
其中错误标志由累计错误数决定，错误数是本轮总数。
只有汇总帧完整读完才确认本轮完成、允许进入下一轮；明细帧不会推进循环。
没有错误时只发送汇总帧。关闭详细日志时只发送汇总帧。
模式 0/1 仍使用原有 11 字节完成帧，即使字节 19 为 1 也不发送明细。

## 缓冲与轮询

FPGA 比较速度远高于 SPI 传输速度。这里使用单条错误缓存及暂停反馈，
在缓存尚未发送完时保持 MRAM 地址、数据流水线、计时和控制引脚状态，
避免后续比较覆盖待发送的错误。明细发送完成后恢复执行。
因此，错误多或上位机轮询慢时，测试耗时会增加；上位机停止读取时，
测试会停在待发送错误处。关闭详细日志或没有错误时不产生该暂停。
这会延长发生错误时的 MRAM 读周期，测量吞吐量时应关闭详细日志。

保持原有 SPI 模式 0、每次 CS 最多一帧的约定；上位机可继续每次读取 64 字节。
有效帧结束后填零；没有就绪帧时整次轮询返回零。不要因为读到一条明细就认为本轮结束。
读帧中途拉高 CS 不消费记录，下次 CS 从帧头重新发送。
接收有效的新配置并启动新测试时会清除旧的待发送记录和完成事件。

错误快照来自原有比较条件：较早的比较使用与 `dout_ref` 同时保存的地址，
较晚的比较使用 `addr_d` 和 `dout_d1`，避免发送期间信号变化或地址错位。
本次工作保留原有比较时点和地址覆盖策略。

## 仿真

需要 Icarus Verilog 12、`vvp`、Python 3，以及包含 `a317d2b` 的 Git 历史。

```sh
bash tests/run_spi_detail.sh
bash tests/run_spi_reports.sh
bash tests/run_top_timing.sh
```

新增协议测试检查 25 字节字段、完整 22 位地址、快照保持、截断重试、
明细优先于汇总、累计错误标志，以及模式 0/1 和关闭日志的兼容性。
完整 `top` 测试通过真实 SPI 配置注入数字比较错误，覆盖两种比较路径、
慢轮询期间 MRAM 状态保持、跨循环计数、无错误路径，以及有待发送记录时同模式重新启动。
旧回归继续逐周期对比关闭详细日志时的控制状态，并校验 11/17 字节帧。

仿真使用理想时钟/TRNG 模型及数字读值注入，不验证物理 MRAM、模拟信号质量、
实际随机性、外部 SPI 输入输出约束或布局布线时序。云环境没有 Vivado，未生成新 bitstream。

## ab8e418 实现后的时序调整

`timing_bundle_20261103_212058.rpt` 对应 ab8e418，包含已布线路径，
WNS 为 −0.965 ns、TNS 为 −104.970 ns，250 个 setup 失败端点；
WHS 为 +0.056 ns，hold 失败端点为 0。
最差路径从 `rd_en_d2` 经比较时点计算、错误判断，到错误快照的 CE。
54 个快照 CE 端点失败，另外有 38 个快照数据端点及错误脉冲路径失败。
计数器、数据/引脚控制和调试逻辑也存在负裕量。

后续候选调整：

- 比较时点 `AVQV-AVAV` 及 EN/WN/UBN/LBN 释放时点在配置提交时预先计算，
  与基本参数同拍生效；保留原来的 21 位减法下溢、写模式回退及 x8 参数覆盖。
  AVQV 沿用原逻辑固定选择读参数；WN 释放偏移也沿用原逻辑固定选择写参数。
- 同一时钟边沿分别采样早/晚比较的操作数，再由寄存的一位选择信号供错误缓存取用。
  完整错误判断不再驱动整组快照的 CE 或数据选择器；错误事件不增加流水线延迟。
- 高扇出的宽位相等比较划分为独立 LUT 小组，读写两组先比较再选择结果；
  地址计数器的大小比较也分组并行计算。保留原有比较宽度及高位检查。

回归仍对比原 RTL 的控制状态和引脚，并增加预计算参数的逐拍一致性、减法下溢、
读写不同周期、大小比较边界及 x8 配置检查。详细错误帧的地址/数据快照、
暂停、重试及重新启动测试继续运行。

本次功能回归通过：617,129 个周期的原 RTL 状态/引脚对比、591,752 个边界条件比较、
10 个完整控制器普通报告、518 次 SPI 轮询和 13 次配置检查，以及包含 20 条实际输出
明细的完整控制器故障注入测试。协议层的明细字段及重试测试也通过。

这些调整针对报告中的逻辑路径，尚无新的 Vivado 布线结果，不能视为时序已收敛。
调试核内部路径也需要在新实现报告中复查。重新 Reset 综合及实现后上传新 bundle；
继续使用真实 200 MHz 时钟约束，当前仓库旧 bitstream 不代表这些源码调整。
